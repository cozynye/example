# 고객 인터뷰 가이드

## 목적
아이디어의 시장 수요를 **실제 사람의 말**로 검증하는 것.
스코어링 점수가 아무리 높아도 고객 인터뷰 없이 "진행" 결정하지 않는다.

## 인터뷰 규칙

### Do
- 열린 질문으로 시작 ("어떻게 하세요?", "어떤 점이 불편하세요?")
- 지불 의향을 반드시 물어보기 ("월 얼마까지 가능하세요?")
- 예상치 못한 문제/니즈에 귀 기울이기
- 인터뷰 직후 바로 기록하기

### Don't
- 솔루션을 먼저 설명하지 않기 (문제부터 확인)
- "이 서비스 쓰시겠어요?" 같은 유도 질문 하지 않기
- 한 명의 열정적 반응에 올인하지 않기 (최소 3-5명)
- 인터뷰를 판매로 만들지 않기

## 인터뷰 채널별 접근법

### 인스타 DM
```
안녕하세요 사장님! [비즈니스]를 정말 잘 운영하시는 것 같아서
여쭤보고 싶은 게 있는데요.
[관련 문제]는 어떻게 관리하고 계세요?
개발자로서 이 분야 서비스를 만들어볼까 고민 중인데,
실제로 사장님들이 어떤 불편을 겪으시는지 궁금합니다 🙏
```

### 커뮤니티 (아프니까사장이다, 네이버 카페 등)
```
[업종] 운영하시는 분들께 질문드립니다!
[관련 문제]는 어떻게 처리하고 계세요?
개발자인데 이 문제를 해결하는 도구를 만들어볼까 고민 중이라
실제 현장의 목소리가 궁금합니다.
```

### 지인/네트워크
```
혹시 주변에 [관련 업종] 하시는 분 계세요?
[관련 문제] 해결하는 서비스 아이디어가 있는데
실제로 그런 불편이 있는지 여쭤보고 싶어서요.
```

## 인터뷰 결과 판단 기준

| 응답 패턴 | 판단 |
|---------|------|
| 5명 중 3명+ "돈 내겠다" | ✅ 강한 수요 → 즉시 개발 |
| 5명 중 2명 "돈 내겠다" | ⚠️ 약한 수요 → 피봇 고려 |
| 5명 중 1명 이하 | ❌ 수요 없음 → 폐기 |
| "무료면 쓰겠다" 만 | ⚠️ 유료 전환 어려움 → 모델 재검토 |
| 예상 못한 다른 문제 발견 | 💡 새 아이디어로 분리 |

## 인터뷰 수량 가이드
- **72시간 검증용**: 최소 3명 (빠른 판단용)
- **MVP 개발 전**: 5-10명 (확신용)
- **런칭 전**: 베타 테스터 3-5명 확보
