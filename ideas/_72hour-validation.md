# 72시간 검증 프로세스

## 왜 72시간인가?
- **Taleb**: 작은 베팅 여러 개 > 큰 베팅 하나. 72시간이면 실패해도 손실 최소.
- **Drucker**: 고객과 대화 없이 진행하면 안 됨. 72시간이면 최소 3명과 대화 가능.
- **Meadows**: 피드백 루프를 빨리 돌려야 학습 속도가 빨라짐.

## 프로세스

```
Hour 0-8: 준비
├─ 검증 방법 선택 (아래 중 1-2개)
├─ 타겟 리스트 작성 (10명+)
└─ 메시지/콘텐츠 준비

Hour 8-48: 실행
├─ 인터뷰 실시 (최소 3명)
├─ 또는 랜딩페이지 배포 + 공유
├─ 또는 커뮤니티 글 작성
└─ 또는 크몽/숨고 서비스 등록

Hour 48-72: 판단
├─ 반응 수집 & 정리
├─ 스코어 업데이트
└─ 결정: 진행 / 피봇 / 폐기
```

## 검증 방법 (난이도 순)

### 1. 크몽/숨고 등록 (가장 쉬움)
- 서비스 등록 → 1주 내 문의 확인
- 비용: 0원
- 검증 기준: 문의 3건+ = 수요 있음

### 2. 커뮤니티 글 작성
- "이런 서비스 만들면 쓰시겠어요?" 형태
- 채널: 아프니까사장이다, 관련 네이버 카페, Reddit
- 비용: 0원
- 검증 기준: 긍정 댓글 5개+ = 관심 있음

### 3. 고객 인터뷰
- DM, 전화, 대면으로 최소 3명
- 비용: 0원 (시간만 투자)
- 검증 기준: 3명 중 2명+ "돈 낼 의향 있다"

### 4. 랜딩페이지
- 1페이지 랜딩 + 사전등록 폼
- 비용: 0원 (Vercel + Tally)
- 검증 기준: 사전등록 10명+ = 강한 수요

## 검증 결과표

| 항목 | 성공 기준 | 실패 시 |
|------|---------|--------|
| 고객 인터뷰 | 3/5명 지불 의향 | 피봇 or 폐기 |
| 랜딩페이지 | 10+ 사전등록 | 메시지 수정 후 재시도 |
| 커뮤니티 반응 | 5+ 긍정 댓글 | 문제 재정의 |
| 크몽 등록 | 3+ 문의 (1주) | 가격/설명 수정 |

## 규칙
1. 72시간 내에 결론을 내야 함 — 무한 리서치 금지
2. 결과가 애매하면 "보류"가 아니라 "1주 더 관찰" 후 최종 판단
3. 동시에 2-3개 아이디어를 병렬로 검증 가능
4. 검증 결과는 반드시 `ideas/[아이디어명].md`에 기록
