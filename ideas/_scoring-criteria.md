# 아이디어 평가 기준

## 점수 체계
각 기준 1-5점, 가중 합산. **3.5점 이상이면 72시간 검증 진행. 검증 통과 후 `projects/`에서 개발.**

## 평가 기준 (v2 — 전문가 패널 개정)

| 기준 | 가중치 | 1점 | 3점 | 5점 |
|------|--------|-----|-----|-----|
| 시장 검증 | 25% | 추측만 | 유사 서비스 존재 | 고객 인터뷰로 지불 의향 확인 |
| 수익 잠재력 | 15% | 주 1만원 미만 | 주 5-10만원 | 주 20만원+ |
| 경쟁 강도 | 15% | 무료 대체재 + 대기업 존재 | 경쟁자 있지만 빈틈 존재 | 경쟁 거의 없는 니치 |
| 첫 수익까지 시간 | 10% | 8주+ (MVP 완성 후 마케팅) | 2-4주 (랜딩+사전등록) | 72시간 내 (즉시 판매 가능) |
| 실패 비용 | 10% | 4주+ 투자 후 피봇 불가 | 2주 투자, 일부 재활용 | 72시간 검증, 즉시 중단 가능 |
| MVP 개발시간 | 10% | 2개월+ | 4주 | 1주 이내 |
| 반복 수익 | 10% | 1회성 | 반복 구매 가능 | 월 구독 모델 |
| 기술 적합성 | 5% | 새 스택 필요 | 일부 활용 | 기존 역량 100% |

### 변경 이유 (전문가 패널 합의)
- **첫 수익까지 시간 🆕**: 4주 수익 0원 상태에서 가장 중요한 지표. 실행-학습 루프 속도 결정 (Christensen, Taleb)
- **실패 비용 ↑5%→10%**: 1인 개발자에게 실패 비용은 생존 문제 (Taleb)
- **기술 적합성 ↓10%→5%**: 고객은 기술 스택을 신경 쓰지 않음 (Christensen)
- **수익 잠재력 ↓20%→15%**: 장기 잠재력보다 단기 실현 가능성이 우선 (Drucker)
- **MVP 개발시간 ↓15%→10%**: 서비스형 모델은 MVP 없이 시작 가능 (Godin)

## 계산 방법
```
총점 = (시장검증×0.25) + (수익×0.15) + (경쟁×0.15) + (첫수익시간×0.10) + (실패비용×0.10) + (MVP×0.10) + (반복수익×0.10) + (기술적합성×0.05)
```

## 결정 프로세스

```
아이디어 발견
  ↓
스코어링 (30분 이내)
  ↓
3.5점 미만 → 폐기 or backlog
3.5점 이상 → 72시간 검증 시작
  ↓
72시간 검증 (아래 중 최소 1개)
  ├─ 랜딩페이지 → 사전등록 10명+
  ├─ 커뮤니티 글 → 반응 확인
  ├─ 잠재 고객 인터뷰 3명+
  └─ 크몽/숨고 등록 → 문의 확인
  ↓
검증 실패 → 보류 or 폐기
검증 성공 → projects/에서 MVP 개발 (2주 이내)
```

## 점수대별 판단
- **4.0+**: 72시간 검증 즉시 시작
- **3.5-3.9**: 검증 가치 있음 (이번 주 내 시작)
- **3.0-3.4**: 보류 (추가 리서치 필요)
- **3.0 미만**: 폐기

## 핵심 원칙 (전문가 패널 합의)
- **Christensen**: 시장 검증이 가장 중요한 기준 — 돈을 내는 사람이 있어야 함
- **Porter**: 경쟁 강도를 반드시 평가 — 무료 대체재가 있으면 치명적
- **Taleb**: 실패 비용을 최소화 — 작은 베팅 여러 개 > 큰 베팅 하나
- **Drucker**: 고객과 대화 없이 "진행" 결정하지 말 것
- **Meadows**: 72시간 검증 → 피드백 루프를 빨리 돌려야 함
- **Godin**: SaaS 구독 전에 Productized Service로 검증 — 첫 수익이 모든 것을 바꿈
- **Collins**: 플라이휠 첫 바퀴를 빨리 돌리는 아이디어가 좋은 아이디어

## 전략 전환 (W14 패널 토론 결과)
- **기존**: 아이디어 → 스코어링 → 72시간 검증 → MVP 개발 → 고객 확보
- **신규**: 아이디어 → 서비스형 등록(크몽/숨고) → 첫 수익 → 반복 패턴 자동화 → SaaS 전환
- **근거**: 4주 리서치 후 매출 0원, 고객 대화 0건. 서비스형이 SaaS보다 첫 수익이 빠름
